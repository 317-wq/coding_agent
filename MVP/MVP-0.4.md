# MVP-0.4 · 变更安全与失败恢复

> 基线：PROJECT.md v1.3
> 前置版本：MVP-0.3
> 日期：2026-10-17

## 1. 本版范围

本版在 MVP 0.3 的任务规划、上下文管理和完成判定基础上，补充代码变更的安全闭环：

1. 读取 Git 仓库状态和任务产生的文件差异，为执行前后对比提供依据。
2. 在写入或删除前保存任务级文件快照，只跟踪本次任务实际触碰的路径。
3. 在工具连续失败、测试失败或完成判定阻塞时生成恢复决策，经用户授权后回滚并重新规划。

**不包含：**自动提交、分支切换、`reset` / `checkout` / `clean` 等写入型 Git 操作、跨任务持久记忆、评测报告、通用命令执行工具和无人确认的自动回滚。

## 2. 本版用户路径

> 用户指定工作区并输入任务 → Agent 探索项目并读取 Git 状态 → 执行写入前保存相关路径快照 → 按计划调用工具并验证结果 → 成功时输出变更摘要 → 连续失败或验证阻塞时生成恢复决策 → 用户确认后恢复本次任务触碰的路径 → 根据恢复结果停止或重新规划。

## 3. 相对上一版的增量

- 架构 / 模块改动：新增只读 Git 信息、任务级变更快照、恢复决策和授权回滚，并接入 Agent Loop 与 Trace。
- 技术选型改动：无；继续使用 Python 标准库调用 Git，可用性由运行环境检查，不新增 GitPython。
- 接口改动：新增只读 Git、变更快照和失败恢复接口；已同步至 `PROJECT.md v1.3`。
- 安全约束：回滚只处理本次任务已记录路径，禁止使用 `git reset --hard`、`git checkout --` 或 `git clean`；执行回滚前必须获得明确授权。
- 本版依赖：沿用 MVP 0.3 的工作区、工具注册、计划状态、上下文、完成判定和 Trace，不新增外部依赖。

## 4. 本版要实现的模块功能

> 按依赖顺序排，勾选代表已完成。

- [x] **Git 仓库识别**：判断工作区是否位于 Git 仓库，返回仓库根目录、当前分支和可用状态。
- [x] **只读 Git 工具**：通过工具注册表提供 `status` 和 `diff` 查询，限制输出长度并拒绝写入型 Git 参数。
- [ ] **任务级变更快照**：在首次写入或删除某个路径前保存文件内容、权限和“原本不存在”状态，避免重复快照。
- [ ] **变更集管理**：记录本次任务创建、修改、删除的路径，并生成执行前后差异摘要。
- [ ] **恢复决策**：根据连续工具失败、测试失败、计划失败和完成判定阻塞，返回继续、停止、重新规划或建议回滚。
- [ ] **授权回滚**：用户明确同意后，仅恢复本次任务触碰的路径；拒绝授权时保留现场并停止恢复。
- [ ] **Agent Loop 适配**：任务执行前初始化变更会话，失败时进入恢复判断，回滚成功后刷新项目快照和计划。
- [ ] **Trace 适配**：记录 Git 基线、快照创建、路径变更、恢复决策、授权结果和回滚结果。
- [ ] **测试补充**：覆盖非 Git 工作区、脏工作区保留、创建/修改/删除恢复、拒绝授权、恢复后重新规划和历史测试回归。

## 5. 本版验收标准

- [ ] Git 工作区能返回稳定、可序列化的仓库信息、状态和受限差异；非 Git 工作区能明确降级，不影响普通任务执行。
- [ ] Git 能力保持只读，模型不能通过该工具执行提交、重置、切换、清理或任意命令。
- [ ] 文件首次变更前会保存快照，同一路径后续多次修改不会覆盖原始快照。
- [ ] 回滚能删除本次新建文件、恢复本次修改或删除的文件，并保留原始权限。
- [ ] 回滚不处理未被本次任务触碰的路径，不使用仓库级强制恢复命令，不覆盖无关的预存改动。
- [ ] 失败恢复决策包含触发原因、建议动作和可恢复路径，且回滚必须经过用户明确授权。
- [ ] 回滚完成后 Agent 能刷新项目快照；需要继续时生成新计划，不沿用已失败计划的运行状态。
- [ ] Trace 能还原 Git 基线、任务变更、失败原因、授权过程和恢复结果。
- [ ] `uv run pytest -q` 通过本版新增测试，且 MVP 0.3 的全部测试继续通过。

## 6. 本版风险与待办

- 脏工作区可能同时包含用户原有改动和 Agent 改动，快照必须以任务开始后的首次触碰为边界，不能把整个仓库恢复到 Git HEAD。
- 文件在快照后被用户或外部进程再次修改时，直接回滚可能覆盖新内容；实现时需要检测冲突并停止自动恢复。
- 大文件、二进制文件和符号链接需要设置明确限制，避免快照占用过多内存或突破工作区边界。
- 非 Git 工作区仍应支持文件快照和恢复，Git 信息只用于增强可观察性，不作为回滚前提。
- 本版先实现单次进程内恢复；跨进程持久快照、崩溃恢复、记忆系统和评测模块留到后续版本。
