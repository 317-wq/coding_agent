# MVP-0.3 · 任务规划与执行控制

> 基线：PROJECT.md v1.2
> 前置版本：MVP-0.2
> 日期：2026-10-16

## 1. 本版范围

本版在 MVP 0.2 的工作区、项目探索和规范化工具链基础上，增强 Agent 核心控制层：

1. 对用户任务进行轻量复杂度判断，区分直接执行和需要规划的任务。
2. 为复杂任务生成结构化步骤计划，并跟踪步骤状态。
3. 管理任务上下文和完成判定，让 Agent 能根据计划、工具结果和测试结果决定是否结束。

**不包含：**记忆系统、回滚模块、评测模块、Git 工具、通用命令执行工具、模型自动选择和完整策略引擎。

## 2. 本版用户路径

> 用户指定工作区并输入任务 → Agent 读取项目快照 → 判断任务复杂度 → 简单任务直接进入执行循环，复杂任务生成步骤计划 → 按步骤调用注册工具 → 更新上下文和步骤状态 → 验证结果并输出总结。

## 3. 相对基线的增量

- 架构 / 模块改动：在 Agent 核心控制层新增复杂度判断、轻量 Planner、任务状态管理、上下文管理和完成判定。
- 技术选型改动：无；继续使用手写 Agent Loop，不引入 LangGraph。
- 接口改动：`PROJECT.md` 已同步至 v1.2；新增 Planner、任务计划、上下文和完成判定的结构化接口。
- 其他：沿用 MVP 0.2 的工作区边界、项目探索、工具注册、参数校验、授权、结构化结果和 Trace 能力。

## 4. 本版要实现的模块功能

> 按依赖顺序排，勾选代表已完成。

- [x] **任务复杂度判断**：根据任务文本和项目快照判断直接执行或需要规划。
- [x] **结构化任务计划**：生成有序步骤，每个步骤包含目标、状态和完成条件。
- [x] **计划执行状态**：记录当前步骤、已完成步骤、失败步骤和停止原因。
- [x] **上下文管理**：维护任务、项目快照、计划、工具结果和测试结果，限制上下文长度。
- [x] **结果验证与完成判定**：根据计划完成条件、工具结果和测试结果判断任务是否完成。
- [ ] **Agent Loop 适配**：简单任务保持原有路径，复杂任务按计划推进并在失败后重新判断。
- [ ] **Trace 适配**：记录复杂度判断、计划生成、步骤状态、上下文裁剪和完成判定事件。
- [ ] **测试补充**：覆盖简单/复杂任务分流、计划状态流转、上下文限制和完成判定。

## 5. 本版验收标准

- [ ] 简单任务可以跳过 Planner，继续使用现有多轮工具循环。
- [ ] 复杂任务能生成稳定、可序列化的步骤计划。
- [ ] 计划步骤能在执行成功、失败和取消时正确更新状态。
- [ ] Agent 能在上下文达到限制时保留任务、当前步骤和最近工具结果等关键内容。
- [ ] 工具结果和测试结果能参与完成判定，不能仅凭模型文字回复宣称完成。
- [ ] 计划失败或工具失败时，Agent 能停止当前步骤并给出明确原因。
- [ ] Trace 能还原一次任务的复杂度、计划、步骤和最终判定过程。
- [ ] `uv run pytest -q` 通过本版新增测试，且 MVP 0.2 的全部测试继续通过。

## 6. 本版风险与待办

- 复杂度判断过于激进会增加不必要的规划轮次，过于保守则无法体现 Planner 价值。
- 计划步骤需要保持足够抽象，避免和具体工具名称强耦合。
- 上下文裁剪不能丢失工作区边界、用户任务和关键失败信息。
- 完成判定需要防止模型在未验证测试或文件落盘前提前结束。
- 后续版本再考虑记忆系统、回滚、评测和更复杂的多阶段编排。
