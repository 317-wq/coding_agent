# MVP-0.1 · 工具循环 Coding Agent

> 基线：PROJECT.md v1.0
> 前置版本：无（首个 MVP）
> 日期：2026-10-15

## 1. 本版范围

本版以已有 `app` 实现为准，完成一个运行在 `workspace/demo` 沙箱中的多工具 Coding Agent：

1. 通过交互式 CLI 接收编程任务。
2. 由模型自主决定并循环调用文件、搜索、测试和删除工具。
3. 记录执行 Trace，输出任务状态和统计摘要。

**不包含：**自动项目探索器、独立 Plan/Retrieve 节点、记忆、回滚、评测模块、Git 工具和完整的工具注册/策略/授权流水线。

## 2. 本版用户路径

> 用户启动程序并输入任务 → Agent 先查看工作区 → 模型循环调用工具 → 工具在 `workspace/demo` 内执行 → 必要时运行测试 → Agent 输出中文总结和 Trace 摘要。

删除文件或目录时，工具会逐项向用户确认；非删除类修改由模型通过工具直接执行。

## 3. 相对基线的增量

- 架构 / 模块改动：落地 CLI、Model Adapter、Agent Loop、沙箱工具和执行追踪的最小实现。
- 技术选型改动：无。
- 接口改动：实现模型工具调用接口；实现文件、目录、搜索、测试和删除工具；工具统一返回文本结果。
- 本版依赖：`pydantic`、`pydantic-settings`、`openai`、`pytest`、`rg`；Trace 使用标准库实现。具体版本以项目依赖配置为准。

## 4. 本版要实现的模块功能

- [x] **配置管理**：从 `.env` 读取 Qwen API 配置。
- [x] **模型适配**：通过 OpenAI 兼容接口调用 Qwen，并支持工具定义。
- [x] **CLI 入口**：交互式输入任务，支持 `exit` / `quit` 退出。
- [x] **沙箱路径控制**：工具仅允许访问 `workspace/demo`，拒绝绝对路径、越界路径和符号链接。
- [x] **文件工具**：列出、读取、创建目录、创建文件、编辑文件。
- [x] **搜索工具**：使用 `rg` 搜索关键词，并限制结果数量、输出大小和执行时间。
- [x] **测试工具**：在沙箱内运行 pytest，设置超时并隔离敏感环境变量。
- [x] **删除确认**：删除文件和目录前必须由用户输入 `y` 确认。
- [x] **Agent Loop**：支持多轮模型请求、工具调用上限、执行轮数上限和错误回传。
- [x] **执行 Trace**：记录模型请求、工具调用和任务状态，清理密钥、敏感文件名和过长内容。

## 5. 本版验收标准

- [x] 能启动 CLI 并输入任务，输入 `exit` 或 `quit` 能退出。
- [x] Agent 能在 `workspace/demo` 内查看文件、读取内容并完成创建或编辑。
- [x] 能使用 `rg` 搜索代码并将结果回传模型。
- [x] 能运行 pytest 并返回通过、失败或超时结果。
- [x] 删除文件和目录时，拒绝确认不会执行删除。
- [x] 访问沙箱外路径、绝对路径或符号链接时会被拒绝。
- [x] 任务结束、失败、中断或达到上限时能输出 Trace 摘要。

## 6. 本版风险与待办

- 当前模型配置固定使用 Qwen 的第一个模型，后续再扩展模型选择和统一配置入口。
- 工具调用结果目前以文本返回，后续可统一为结构化结果并增加参数校验。
- 当前工作区固定为 `workspace/demo`，后续再支持 CLI 传入工作区。
- 后续版本在本版基础上增加项目探索、规划、授权、回滚和评测能力。
