# MVP-0.5 · 任务结果报告与可观测性增强

> 基线：PROJECT.md v1.27
> 前置版本：MVP-0.4
> 日期：2026-10-17

## 1. 本版范围

本版在 MVP 0.4 的安全执行、测试恢复和 Trace 基础上，增强一次任务结束后的结果表达与可审查性：

1. 统一生成结构化任务结果，明确任务状态、修改文件、测试证据、恢复动作和未完成原因。
2. 将执行 Trace、变更集和完成判定汇总为面向用户的简洁报告，同时保留机器可读数据。
3. 支持任务未完成或被阻塞时输出下一步建议，避免只返回一段模型自由文本。

**不包含：**跨任务记忆、自动提交与 Pull Request、评测指标与报告平台、后台任务、复杂多 Agent 编排和无人确认的高风险操作。

## 2. 本版用户路径

> 用户输入任务 → Agent 按 MVP 0.4 的目标计划执行 → 工具结果、测试结果和 Trace 持续记录 → 完成判定或恢复流程结束 → Agent 汇总变更文件、测试证据和恢复记录 → CLI 输出人类可读总结，并提供结构化结果供后续调用。

## 3. 相对上一版的增量

- 架构 / 模块改动：在 Agent 核心与 Trace 之间增加任务结果汇总层，在 CLI 增加统一报告渲染。
- 技术选型改动：无；继续使用现有 Python 数据类、JSON 序列化和 Trace，不引入新的外部服务。
- 接口改动：新增 `TaskResult` / `TaskReport` 结构化结果，统一描述完成、停止、失败和阻塞状态；新增报告渲染入口。
- 结果约定：报告必须区分代码修改、测试证据、恢复动作、用户授权结果和未完成原因，不以模型总结作为唯一来源。
- 集成约定：`Agent.run()` 完成后将结果保存到 `agent.last_result`；CLI 默认渲染中文报告，可通过 `--output-format json` 输出同一份结构化结果。
- 基线同步：上述 Agent/CLI 接口和任务级安全约束已同步至 `PROJECT.md v1.5`。
- 验收控制同步：安全边界和一次性验收任务的轻量规划、失败即停约定已同步至 `PROJECT.md v1.6`。
- 完成判定同步：必要步骤、失败工具和有效测试证据的严格完成规则已同步至 `PROJECT.md v1.7`。
- 工具路径同步：统一路径规范化和批次失败/取消中断规则已同步至 `PROJECT.md v1.8`。
- 重复操作同步：文件状态核验、重复写操作去重和幂等编辑规则已同步至 `PROJECT.md v1.9`。
- 快照与回滚一致性同步：写前快照、实际修改 Trace、任务初始状态净变更口径及回滚后核验规则已同步至 `PROJECT.md v1.10`。
- 最终报告真实性同步：结束前统一核验文件内容摘要、Git 状态、测试 Trace 和调用统计，禁止模型总结充当事实证据的规则已同步至 `PROJECT.md v1.11`。

- 错误修复恢复同步：循环导入、代码导入和可修复收集错误的“分析、修改、重跑”两轮恢复流程，以及回归测试规划规则已同步至 `PROJECT.md v1.13`。

## 4. 本版要实现的模块功能

> 按依赖顺序排，勾选代表已完成。

- [x] **任务结果模型**：定义稳定、可序列化的任务状态、停止原因、修改摘要、测试证据和恢复记录字段。
- [x] **结果汇总器**：从 Agent 上下文、变更集、完成判定和 Trace 生成唯一任务结果，不重复解析模型自由文本。
- [x] **测试证据摘要**：保留用户指定测试路径、退出码、通过/失败状态及错误分类。
- [x] **变更摘要输出**：按创建、修改、删除和未恢复路径分组展示文件变化。
- [x] **恢复记录输出**：展示自动修复次数、恢复决策、授权结果、回滚结果和用户拒绝回滚后的处理。
- [x] **CLI 报告渲染**：提供简洁中文摘要，同时支持 JSON 结果输出。
- [x] **未完成任务建议**：任务被阻塞、达到限制或需要用户处理时，给出明确原因和下一步建议。
- [x] **Trace 关联**：报告能够引用关键 Trace 事件，保证结果可追溯但不泄漏敏感信息。
- [x] **测试补充**：覆盖成功、测试失败后修复、达到修复上限、回滚成功、拒绝回滚和环境错误等报告场景。

## 5. 本版验收标准

- [ ] 任意任务结束后都能得到稳定的结构化结果，状态至少包括 `completed`、`stopped`、`failed` 和 `blocked`。
- [ ] 结果中的修改文件来自实际变更集，不能只依据模型文字总结。
- [ ] 测试摘要保留指定测试路径、退出码和错误分类，并能区分断言失败、测试代码错误、收集冲突和环境错误。
- [ ] 报告能准确展示自动修复次数，首次测试运行不计入修复次数。
- [ ] 报告能区分回滚成功、回滚冲突、用户拒绝回滚和未触发回滚。
- [ ] 任务未完成时，报告包含阻塞原因、已完成内容和下一步建议，不伪装成成功。
- [ ] CLI 人类可读输出与 JSON 结构化输出表达同一份任务结果。
- [ ] 报告中的路径遵循工作区相对路径约定，不泄漏工作区外路径和敏感配置。
- [ ] `uv run pytest -q` 通过本版新增测试，且 MVP 0.4 的全部测试继续通过。

## 6. 本版风险与待办

- 结果汇总不能因为上下文裁剪而丢失关键测试、变更或恢复证据，需要明确数据来源和保留策略。
- 报告内容需要控制长度，避免把完整 Trace 或大段测试输出直接回显给用户。
- JSON 接口字段一旦稳定，后续版本应保持向后兼容或提供版本字段。
- 评测指标、跨任务记忆和外部协作能力继续留到后续版本。
