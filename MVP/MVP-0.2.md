# MVP-0.2 · 项目探索与工具规范化

> 基线：PROJECT.md v1.1
> 前置版本：MVP-0.1
> 日期：2026-10-15

## 1. 本版范围

本版在 0.1 多工具 Agent Loop 基础上，增强工作区管理和工具系统：

1. CLI 支持指定工作区，不再固定使用 `workspace/demo`。
2. 增加项目探索能力，帮助 Agent 了解目录结构和代码位置。
3. 将工具调用统一收敛到注册、参数校验和结构化结果流程。
4. 对删除等高风险操作保留用户确认。

**不包含：**记忆系统、回滚、评测、Git 工具、复杂 Planner、模型自动选择和完整策略引擎。

## 2. 本版用户路径

> 用户通过 CLI 指定工作区并输入任务 → Agent 扫描项目结构 → 使用搜索工具定位相关代码 → 模型调用注册工具执行操作 → 高风险操作请求确认 → 返回结构化结果和 Trace 摘要。

## 3. 相对基线的增量

- 架构 / 模块改动：新增项目探索器的基础能力；工具调用增加注册表和统一执行入口。
- 技术选型改动：无；继续使用 uv 管理依赖。
- 接口改动：`PROJECT.md` 已同步至 v1.1；CLI 增加工作区参数；工具执行结果统一包含状态、结果和错误信息；高风险工具保留授权确认。
- 本版依赖：沿用 0.1 的 `pydantic`、`pydantic-settings`、`openai`、`pytest`、`rg`，不新增外部依赖。

## 4. 本版要实现的模块功能

- [x] **工作区参数**：CLI 支持传入工作区路径，并校验路径存在且为目录。
- [x] **工作区解析**：启动时将工作区解析为受控根目录，所有工具共享同一工作区上下文。
- [x] **项目探索器**：提供目录扫描、基础项目结构分析和关键信息提取。
- [ ] **工具注册表**：集中注册工具名称、描述、参数定义、执行函数和风险级别。
- [ ] **参数校验**：工具执行前校验工具名称和参数，拒绝未知字段及无效参数。
- [ ] **结构化工具结果**：统一返回成功、失败、取消三类状态及结果信息。
- [ ] **高风险授权**：删除工具继续要求用户明确输入 `y`，拒绝时返回取消状态。
- [ ] **Agent 适配**：将结构化工具结果正确回传给模型，不破坏现有多轮循环和上限控制。
- [ ] **Trace 适配**：记录工作区、工具状态和错误信息，同时继续脱敏敏感数据。
- [ ] **测试补充**：在 `workspace` 下增加工具注册、工作区边界、结构化结果和授权流程测试。

## 5. 本版验收标准

- [ ] 不指定工作区时保持明确的默认行为，指定有效工作区时 Agent 能在该目录工作。
- [ ] 指定不存在的路径、文件路径或工作区外路径时，CLI 能拒绝启动或拒绝访问。
- [ ] Agent 能扫描并返回目标项目的基础结构信息。
- [ ] 所有模型工具调用都经过注册表和参数校验。
- [ ] 未知工具、缺少必填参数和多余参数都返回结构化错误。
- [ ] 创建、读取、编辑、搜索和测试工具在新工作区中正常工作。
- [ ] 删除操作拒绝确认时返回取消状态且文件保持不变。
- [ ] Trace 能记录工具状态和工作区相关事件，并通过已有脱敏检查。
- [ ] `uv run pytest -q` 至少通过本版新增测试。

## 6. 本版风险与待办

- 工作区切换后需要重新检查路径解析、符号链接和子进程工作目录，避免安全边界回归。
- 结构化结果会改变 Agent 与模型之间的消息内容，需要兼容工具失败和取消场景。
- 项目扫描先限制数量、文件大小和忽略目录，复杂架构分析留到后续版本。
- 后续版本再增加 Planner、记忆、回滚和评测能力。
