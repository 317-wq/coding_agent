# MVP-0.9 · 计划可执行性与完成判定可信性

> 基线：PROJECT.md v1.44
> 前置版本：MVP-0.8
> 日期：2026-10-24

## 1. 本版范围

本版修复 MVP-0.8 之后一次真实运行暴露的三个 P0 缺陷。它们共同导致：**工作区代码正确、测试全过，任务却被报成 `blocked`，并空转 96 秒。**

1. **C1 计划步骤必须可执行** —— 计划里不允许出现任何工具都无法匹配的“需求细节步骤”。
2. **C2 测试步骤必须真实执行** —— 目标里写了“运行测试确认通过”的步骤，不能只创建测试文件就算完成。
3. **C3 终止事件与停止原因完整** —— 任务结束时必须有终止事件；`stop_reason` 不允许退化成“任务未完成。”。

**不包含**（见第 6 节待办）：非交互模式下删除授权策略、空转轮次收敛、Git 报告口径、Planner 支持多文件并行步骤。

## 2. 本版用户路径与复现场景

复现命令：

```bash
uv run coding-agent --workspace ./workspace/trace_probe --debug --max-steps 25 --max-tool-calls 60
```

任务文本：

> 实现 calculator.py，提供 add(a, b) 和 divide(a, b) 两个函数；divide 在 b 为 0 时抛出 ZeroDivisionError。然后编写 tests/test_calculator.py 覆盖这两个函数，最后运行测试确认通过。

修复前的事实：

- 第 5 轮（19 秒）时测试已通过，工作区正确（后续 `pytest` 独立验证 10 passed）；
- 计划有 3 步，其中第 2 步「完成：divide 在 b 为 0 时抛出 ZeroDivisionError」对全部 6 类工具 `match_step` 均返回 `None`；
- 该步骤永远 `pending`，完成判定永远返回 `仍有必要计划步骤未完成`；
- Agent 继续空转 19 轮（模型请求 24 次、工具调用 20 次，总耗时 116 秒），期间创建并试图删除 `tests/__init__.py`；
- 删除被非交互授权拒绝（`cancelled`），完成判定改为 `存在失败或取消的工具结果`，触发回滚建议；
- 回滚被拒后**没有任何终止事件**，报告最终写 `状态：blocked / 未完成原因：任务未完成。`

本版目标：同一任务在 ≤8 轮内以 `completed` 结束，`stop_reason` 为空。

## 4. 本版要实现的模块功能

> 按依赖顺序排，一项验收通过后才进入下一项。

- [ ] **C1 · 计划步骤必须可执行**

  - 现象：真实任务的计划第 2 步是需求细节“divide 在 b 为 0 时抛出 ZeroDivisionError”，不含任何动作词，任何工具都匹配不到，导致任务永远无法完成。
  - 根因：`TaskPlanner._extract_objectives` 按 `；`/`。`/`然后` 等符号切分后直接逐句成步；归并分支只在“分句 >5 或长度 >180 或分句 ≤1”时触发。本次任务 3 个分句、136 字符，正好落在逐句成步的分支里。
  - 改动：
    1. 分句后按动作词过滤：不含实现/修改/创建/新增/删除/修复/重构/编写/补充/运行/验证/阅读/查看/搜索等动作词的片段，并入前一个有效步骤；若没有前一步则并入后一步。
    2. 过滤后若没有有效步骤，回退到既有的“目标归并”（阅读 / 实现 / 编写测试 / 运行测试）。
    3. 计划创建后执行**可匹配性校验**：对每个 `pending` 步骤，用全部已注册工具做一次匹配探测；所有工具都匹配不到的步骤记为 `plan_step_unmatchable` 并从计划中移除（并入前一阶段），避免永久 `pending`。
    4. 记录 `plan_pruned` 事件，保留被移除步骤的原文，便于审查。
  - 完成条件：本次真实任务生成的计划只剩 2 步（实现 / 编写+运行测试）或 3 步且每步至少被一类工具匹配；新增回归测试直接使用该任务文本；`plan_pruned` 事件在 Trace 中可见。

- [ ] **C2 · 测试步骤必须真实执行**

  - 现象：步骤「编写 tests/test_calculator.py 覆盖这两个函数，最后运行测试确认通过」在仅执行 `create_file` 后就被标记 `completed`，而它的目标明确要求“运行测试确认通过”。
  - 根因：`can_complete_step` 的“编写”分支只看**后续**是否存在测试执行步骤（`_has_later_test_execution_step`），不看本步骤目标自身是否要求运行测试。计划里没有独立“运行测试”步骤时，创建文件即可完成。
  - 改动：
    1. 若步骤目标包含运行/验证/测试通过等要求，则该步骤只接受 `run_tests` 作为完成证据。
    2. 否则维持现状：`tests/` 下的真实测试源文件写入即可完成编写步骤。
    3. 新增回归测试：构造含“最后运行测试确认通过”的步骤，断言 `create_file` 不能完成、`run_tests` 可以完成。
  - 完成条件：上述断言成立；既有“编写测试步骤只接受测试源文件”的用例继续通过。

- [ ] **C3 · 终止事件与停止原因完整**

  - 现象：任务以回滚被拒结束，Trace 最后一条是 `user_confirmation_required`，`task_completed`/`task_failed`/`task_stopped` 计数均为 0；报告最终写 `未完成原因：任务未完成。`，丢失真实原因（非交互拒绝授权 + 计划步骤未完成）。
  - 根因：回滚取消分支直接返回原因，不记录终止事件；`TaskResultAggregator._stop_reason` 在找不到终止事件时退化为固定文案。
  - 改动：
    1. `_rollback_and_replan` 在取消与失败分支记录 `task_stopped`，reason 使用面向用户的中文原因。
    2. `TaskResultAggregator` 在无终止事件时，退回使用最近一次 `completion_checked` 的原因；仍为空时才用兜底文案。
    3. `TaskResult.stop_reason` 在完成判定为 `incomplete` 时追加待处理步骤编号，例如“仍有必要计划步骤未完成（step 2）”。
  - 完成条件：本次场景重跑后 Trace 含 `task_stopped`；报告 `未完成原因` 不再等于“任务未完成。”；新增单元测试覆盖“无终止事件时取完成判定原因”。

## 5. 本版验收标准

- [ ] **通用门槛**：每项完成后 `uv run pytest -q` 全绿、`uv run ruff check app tests` 输出 `All checks passed!`。
- [ ] **行为等价**：`uv run pytest tests/test_runner_golden.py -q` 保持 6 passed，快照文件不得修改。
- [ ] **真实复跑**：用第 2 节的命令与任务重跑，要求
  - 状态为 `completed`；
  - `stop_reason` 为空；
  - 模型请求 ≤ 8 次；
  - 工作区 `pytest` 通过；
  - Trace 中不出现 `plan_step_unmatchable` 之外的异常事件。
- [ ] **C1**：`create_task_plan(真实任务)` 不再产生无动作词步骤；`PlanStateManager.prune_unmatchable_steps` 有单元测试。
- [ ] **C2**：含“运行测试”要求的编写步骤只接受 `run_tests`；回归测试覆盖。
- [ ] **C3**：回滚取消路径产生 `task_stopped`；`stop_reason` 兜底逻辑有单元测试；报告中出现待处理步骤编号。
- [ ] **交付纪律**：每项单独提交，每个改动文件单独 `git commit`，消息格式 `<类型>: <简短描述>`；复选框与基线版本只在验收通过后更新。

## 6. 本版风险与待办

- **风险 · C1 的过滤规则**：把“需求细节”并入前一步可能让个别多目标任务的步骤变粗。缓解方式：并入时保留原文到步骤的 `completion_criteria` 或 Trace，且过滤只针对**不含动作词**的片段。
- **风险 · C1 的可匹配性校验**：匹配探测使用代表性参数（`path="."`、`test_path="."`），可能把依赖具体路径的步骤误判为可匹配。因此校验只做“全部工具都匹配不到”这种确定性判断，不追求精确。
- **风险 · C2 的行为收紧**：已有任务若在“编写测试”步骤后没有独立测试执行步骤，可能从“提前完成”变成“等待测试”，表现为轮次增加而不是错误。
- **待办 · 非交互删除**：本次真实运行中，清理自己创建的文件被授权拒绝，`cancelled` 结果永久阻塞完成判定。可选方向：把“非交互不支持删除”做成工具可用性约束，或允许删除本任务创建的文件。
- **待办 · 空转收敛**：即使 C1 生效，仍需要“连续 N 轮无步骤推进”的保护，属于独立小项。
- **待办 · Git 报告口径**：工作区位于被 gitignore 的目录时，报告显示“Git 变更 0 个”，与“创建 3 个文件”并列容易误读。
