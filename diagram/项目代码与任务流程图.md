# Mini Coding Agent 项目流程图

本文按当前代码实现整理，分为代码模块协作关系和单次任务工作流程。图中仅展示主要调用与数据流，未实现的长期记忆、评测等远期模块不在图中。

## 1. 文件 / 模块协作关系

此图回答“哪些文件共同完成一项任务”。连线表示主要调用或数据依赖，不代表每个模块之间都存在直接 import。

```mermaid
flowchart LR
```

### 阅读要点

- `app/core/agent.py` 是任务控制枢纽：它组织计划、模型请求、工具调用、状态更新、恢复和最终结果生成。
- 模型只提出下一步动作；实际工具由 `ToolRegistry` 统一校验、按风险授权并执行，工具结果再回到 Agent 上下文。
- 工作区上下文被文件、搜索、测试、Git 和变更快照共同使用，用于统一路径解析与边界控制。
- `ExecutionTrace` 贯穿模型请求、工具调用、测试与完成核验；最终报告由结构化证据聚合，而不是直接采信模型总结。

## 2. 单次任务工作流程

此图回答“用户提交一个任务后，程序按什么顺序运行”。模型可以在一个任务中多轮决定调用工具或结束；控制层负责守住执行约束和完成条件。

```mermaid
flowchart TD
    Start([用户启动 CLI]) --> Input[指定工作区并输入任务]
    Input --> Init[解析工作区<br/>创建 Agent 与 Trace]
    Init --> Explore[探索项目快照<br/>读取 Git 基线]
    Explore --> Classify{判断任务复杂度}
    Classify -->|需要规划| Plan[生成结构化计划与步骤状态]
    Classify -->|简单任务| Context[初始化任务上下文]
    Plan --> Context
    Context --> Safety[建立任务安全会话<br/>记录约束与变更基线]
    Safety --> Request[组装消息与可用工具]
    Request --> Model[Model Adapter 请求模型]
    Model --> Response{模型返回什么？}

    Response -->|工具调用| Parse[解析调用参数]
    Parse --> Guard[任务级约束与工具可用性检查]
    Guard --> Registry[工具注册表校验参数<br/>检查风险与授权]
    Registry --> Allowed{允许执行？}
    Allowed -->|拒绝 / 取消 / 失败| ToolFailure[记录结构化失败结果与 Trace]
    Allowed -->|允许| Snapshot[写操作按需保存原始状态快照]
    Snapshot --> Execute[执行文件 / 搜索 / 测试 / Git 工具]
    Execute --> Observe[记录工具结果<br/>更新上下文、步骤与变更集]
    ToolFailure --> Observe
    Observe --> StopBatch{本次调用失败或取消？}
    StopBatch -->|是| Request
    StopBatch -->|否，仍有同批调用| Parse
    StopBatch -->|否，批次结束| Request

    Response -->|直接总结| Check[核验计划完成条件<br/>核验明确需求]
    Check --> Complete{所有必要条件满足？}
    Complete -->|否| TestPending{是否有失败测试修改尚未重跑？}
    TestPending -->|是| ForceTest[只开放对应测试目标<br/>必须先重跑验证]
    ForceTest --> Request
    TestPending -->|否| Recover[按失败证据生成恢复决策]
    Recover --> RecoverAction{恢复决策}
    RecoverAction -->|继续 / 重规划| Replan[保留有效修改<br/>刷新或重建计划与上下文]
    Replan --> Request
    RecoverAction -->|建议回滚| AuthorizeRollback{用户授权回滚？}
    AuthorizeRollback -->|拒绝| Blocked[保留当前修改并停止等待确认]
    AuthorizeRollback -->|同意| Rollback[仅恢复本任务触碰路径]
    Rollback --> VerifyRollback{恢复后净变化为零？}
    VerifyRollback -->|否| Blocked
    VerifyRollback -->|是| Replan
    RecoverAction -->|停止 / 不可恢复| Blocked

    Complete -->|是| Final[重新核验文件变化、Git 状态、测试证据与 Trace]
    Final --> Aggregate[聚合 TaskResult<br/>生成中文文本或 JSON 报告]
    Aggregate --> End([CLI 展示结果])
    Blocked --> Final
```

### 关键控制点

- **工具边界**：模型调用不会直接执行；参数校验、工作区检查及高风险授权在工具执行路径中落实。
- **测试顺序**：开发计划还没有测试源文件时暂不开放测试工具；失败测试后若代码已有实际修改，先重跑原测试目标，再继续其他操作。
- **完成条件**：计划步骤、工具/测试证据和用户明确要求共同参与判定；模型自然语言总结本身不能证明任务完成。
- **最终报告**：结束前读取真实变更、Git、测试和 Trace 证据，失败或证据不足时以受阻/未完成状态呈现。
